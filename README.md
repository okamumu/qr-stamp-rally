# qr-stamp-rally

学会・展示会向けの**企業展示スタンプラリー**。来場者は名札のQRを下げているだけでよく、
出展者がブース画面で名札QRを読み取ってスタンプを押す。素の PHP 7.4+ と SQLite だけで動き、
レンタルサーバ（さくら等）にそのまま置ける。

2026年度 電気・情報関連学会中国支部連合大会（約500名・出展8社）で実運用。

## 特徴

- **来場者はスマートフォン不要**。名札のQR（参加証コード）を提示するだけ
- **参加証コードはチェックサム式**（6文字＝5文字＋検査文字）。サーバに発行リストを
  持たないので、名札の印刷側と**データ同期が一切不要**。追加発行も自由
- **ラリーへの参加は受付での「参加登録」1タップ**（真正な名札でも登録するまで無効）
- **出展者はセルフ登録**：紙で渡した登録キーを入力すると、ブース読み取り画面の
  URLとQRがその場で発行される。社名の修正も同じキーで自分でできる
- **管理コンソール**（Basic認証）：イベント名・抽選条件・登録キー発行・
  登録用紙の印刷・受付鍵の再発行・DB初期化がすべて画面で完結
- 外部サービス・フレームワーク・ビルド工程なし。依存は PHP（pdo_sqlite）のみ

## 画面

| 画面 | パス | 使う人 |
|---|---|---|
| 来場者ページ（進捗） | `/?n=参加証コード` | 来場者（名札QRの行き先） |
| ブース登録 | `enroll.php` | 出展者（登録用紙のQRから） |
| ブース読み取り | `booth.php?b=…&key=…` | 出展者（enrollが発行） |
| 受付（参加登録・抽選） | `admin.php?admin=鍵` | 受付スタッフ |
| 集計・CSV | `export.php?admin=鍵` | 運営 |
| 管理コンソール | `manage.php`（Basic認証） | 主催者 |

## 仕組み

```
参加証コード = 5文字 + 検査文字1桁
  文字集合: 23456789ABCDEFGHJKLMNPQRSTUVWXYZ（0/O・1/I を除いた32文字）
  検査文字 = ALPH[ Σ_{i=0..4} (i+1) × idx(cᵢ) mod 32 ]
```

- 名札のQRは `https://あなたのサイト/stamp/?n=コード`
- サーバはコードの**形式（検査文字）だけ**を検証する。名札の印刷は好きなツールで
  同じ規則のコードを生成すればよい（Python例は `lib/config.php` のコメント参照）
- スタンプは「どのブースが・どのコードを・いつ読んだか」をサーバのSQLiteに記録。
  来場者の端末には何も保存しない（iOSのコードスキャナは読み取りごとに使い捨ての
  ブラウザ領域で開くため、端末保存方式は成立しない——実機で確認済み）

## セットアップ

1. このリポジトリの中身をドキュメントルート配下（例 `/stamp/`）に置く
2. `lib/secret.example.php` を `lib/secret.php` にコピーし、管理コンソールの
   ID とパスワードの **bcrypt ハッシュ**を書く
   （`php -r "echo password_hash('パスワード', PASSWORD_BCRYPT);"`）
3. SQLite の置き場所を決める。**必ず公開領域の外**に。既定はこのフォルダの4つ上の
   `rentai_stamp/`（さくらで `~/www/<ドメイン>/stamp/` に置いた場合にホーム直下になる深さ）。
   環境変数 `STAMP_DB_DIR` で明示もできる
4. `manage.php` を開き：イベント名・開催日 → 抽選条件（1回目N社／2回目N社・0=全社）→
   出展者の登録キーを発行 → 「未使用キーの登録用紙を印刷」
5. 登録用紙を各出展者へ1枚ずつ渡す（1キー=1ブース）。受付用QRも manage.php から表示できる

### ローカルで試す（Docker）

```sh
docker run -d --name stamp -p 8080:80 -e STAMP_DB_DIR=/tmp/stamp \
  -v "$PWD:/var/www/html/stamp:ro" php:7.4-apache
# lib/secret.php を作ってから http://localhost:8080/stamp/manage.php
```

ブースのスキャンはカメラなしでも `booth.php?b=…&key=…&scan=1&n=コード` で叩ける。

### 事前参加者の一括登録（API）

参加が最初から分かっている人は、受付の鍵で登録APIを叩いて先に登録しておける
（当日の受付タップは飛び込み対応だけになる）。冪等なので何度流しても安全。

```sh
curl "https://…/stamp/admin.php?admin=鍵&api=register&n=参加証コード"
# → {"ok":true,"code":"…","already":false}
```

## 当日の運用

1. **受付**：来場者の名札QRを admin 画面で読み「参加登録する」を1タップ
2. **ブース**：出展者が来場者の名札QRを読む（1件ごとにカメラは閉じる・二重は自動検知）
3. **抽選**：admin でQRを読む→条件を満たしていれば「抽選を実施」→景品はその場で
   （くじ引き等は物理で。システムは条件判定と実施記録だけを持つ）
4. 集計は `export.php`（画面とCSV）

トラブル時：出展者の端末で読めない→booth画面の手入力欄へ。サーバ不調→コードを
手控えして復旧後に手入力。

## 年次・イベントの切り替え

manage.php の「すべて初期化」→ イベント名・抽選条件を設定 → キーを発行、で完了。
コードを編集するのは `lib/secret.php`（認証の更新）だけ。

## 開発ではまった点（先人の轍）

- **クエリ名に `c` を使わない**（Google系サービスの予約と衝突する。名札は `n`、ブースは `b`）
- **iOS のコードスキャナは localStorage を保てない**。読み取りごとに使い捨て領域で開く。
  進捗はサーバに置くこと
- **SQLite を公開領域に置かない**。レンタルサーバではホーム直下など、ドキュメント
  ルートの外へ
