# 企業展示スタンプラリー 2026（名札QR方式）

大会当日（2026-10-17）の企業展示スタンプラリー一式。
サーバは大会サイトと同じさくら（PHP 7.4 + SQLite）、実装は `rentai2026/web/stamp/`。
このフォルダ（Dropbox のみ）には運用資料・抽選の紙・検証スクリプトを置く。

**2026-10-10 の大改修後の姿がこの README の正。** 途中経過は末尾の「履歴」へ。

## しくみ

| 誰が | 何をする |
|---|---|
| 学生 | **名札を下げているだけ。スマートフォンは不要。**（自分の名札QRを読めば進捗を確認できる） |
| 企業 | 登録用紙のキーで**ブースをセルフ登録**し、当日はブース画面で**学生の名札QRを読む** |
| 受付 | admin画面で名札QRを読み**「参加登録」**→ 条件を満たしたら**抽選（紙くじ）**→ 参加賞 |

- 進捗も記録もすべてサーバ（SQLite）。学生の端末には何も保存しない。
- 抽選は **1回目＝NEED1社（既定4）**、**2回目＝NEED2社（既定0＝登録済みの全社）**。
  社数は管理コンソールから変更できる。

> **なぜ企業が読むのか。** 当初は学生が企業QRを読む方式だったが、
> **iOS のコードスキャナは読み取るたびに使い捨ての領域でページを開く**ため、
> 端末に進捗を保存する方式では続きから数えられなかった（2026-09-17 に実機で判明）。
> 企業が読む方式なら、1回の読み取りに「どの企業か」と「どの学生か」の両方が含まれる。

## 参加証コード（名札QR）の仕様

- **コードは6文字**＝先頭5文字＋検査文字1桁。文字は紛らわしい字（0/O・1/I/l）を除いた
  32文字（`23456789ABCDEFGHJKLMNPQRSTUVWXYZ`）。
  検査文字 = `ALPH[ Σ_{i=0..4} (i+1)×idx(cᵢ) mod 32 ]`
- **発行は名簿側**（`次期システム/make_meibo.py` が参加者名簿の各行へ冪等に割り当てる）。
  **サーバは事前登録リストを持たず、チェックサムの検証だけ**を行う
  （`lib/config.php` の `pass_ok()`。Wi-Fi貸出ページも同じ規則）。
  → 名簿とサーバの間にデータ同期が不要。**追加発行＝正本に行を足して名簿を再生成し、
  `次期システム/make_meibo.py --only 氏名` で1枚刷るだけ**
- ただし**チェックサムは「名札が本物か」を保証するだけ**で、ラリーへの参加は
  **受付での「参加登録」**（admin画面で名札QRを読んで1タップ・DBの pass テーブル）が必要。
  未登録の名札を企業が読むと「先に総合受付で参加登録を」と案内される
- QRの中身は `https://rentai-chugoku.org/stamp/?n=コード`。クエリ名に `c` は使わない
  （Google系で予約されており事故のもと。履歴参照）

## 画面とURL

| 画面 | URL | 使う人 |
|---|---|---|
| 学生ページ（進捗） | `/stamp/?n=名札コード` | 学生（名札QRの行き先） |
| 企業ブース登録 | `/stamp/enroll.php` | 企業（登録用紙のQRから） |
| 企業ブース読み取り | `/stamp/booth.php?b=トークン&key=鍵` | 企業（enrollが発行するQR） |
| 受付（参加登録・抽選） | `/stamp/admin.php?admin=鍵` | 総合受付 |
| 集計 | `/stamp/export.php?admin=鍵` | 運営 |
| **管理コンソール** | `/stamp/manage.php`（Basic認証） | 実行委員長・総務 |

鍵の所在：**コードに残る秘密は manage.php の Basic 認証（`MANAGE_USER/PASS`・
lib/config.php）だけ**。受付の鍵（admin/export用）はDB保存で、manage.php に表示・
再発行できる。企業の鍵は enroll 登録時にDBへ発行。**この README には書かない**
（控えは `非公開/大会重要情報まとめ.md`）。

### 管理コンソール（manage.php）でできること

- **大会名・開催日**の変更（登録用紙・enrollページに印字される）
- **抽選条件** NEED1／NEED2（0=全社）の変更（DB保存。config の値は既定値）
- **企業登録キー**の追加発行・使用状況一覧（どのキーをどの社が使ったか）
- **未使用キーの登録用紙の印刷**（`?print=1`・A5×2面/ページ・QR入り）
- **DB初期化**＝「記録のみ」（スタンプ・抽選・参加登録）／「すべて」（企業・キー・設定も。
  年次切替用）。POST後はリダイレクトするのでリロードで二重実行されない

### 企業のセルフ登録と社名修正

- 前日の設営時に**登録用紙（1社1枚・キー1つ）**を渡す。企業は用紙のQRから enroll.php を
  開き、**社名＋キー**で登録 → ブース読み取り画面のURLとQRが即発行される
  （**端末でブックマークしてもらう**）
- **同じキーで社名を入れて再送信＝社名の修正**（QR・URLは不変）。
  空のまま送信＝発行済みQRの再表示。受付で代行するときも同じ導線
- 登録キーの紙の残り＝未登録の社、で進捗を把握できる

## 当日の運用

### 前日（10/16 設営）

1. 各社へ登録用紙を1枚ずつ渡し、その場で登録・ブックマークまで確認
2. 受付端末で admin 画面を開けること・カメラ読み取りを実機確認（リハーサル）

### 当日

1. **受付**：学生が名札を見せたら admin 画面でQRを読み「参加登録する」を1タップ
2. **ブース**：企業が学生の名札QRを読む（1件ごとにカメラは閉じる。二重は自動検知）
3. **抽選**：admin でQRを読む→「抽選できます」→紙くじを引かせる（下の「抽選」節）
4. **参加賞**：菓子を渡す（当落にかかわらず）。admin の「参加賞を渡した」も押す

### うまくいかないとき

1. 学生の端末で読めない → 関係ない（学生は読まない）。企業の端末で読めない →
   **学生を総合受付へ**（booth 画面に手入力欄は無い。受付が admin の手入力か、
   `booth.php?b=…&key=…&scan=1&n=コード` の直叩きで記録する）。駄目なら紙台紙へ切替
2. サーバが不調 → 受付は名札コードを手控えにメモ。復旧後に手入力で消化
3. 全面的に駄目 → 紙台紙へ切替。企業へは「サインでお願いします」と口頭連絡

## 抽選（当日・紙でやる）

**システムは「N社そろったか」を判定するだけで、くじは受付で物理的に引く。**

| ファイル | |
|---|---|
| `抽選/くじ_200枚.pdf` | 三角くじ 200枚（17ページ・A4に12面）。**1等2・2等10・3等50・はずれ138** |
| `抽選/くじ_200枚.html` | 生成元。配分を変えるときはここを直して Chrome で print-to-pdf |
| `抽選/くじ_追加はずれ20枚.pdf` | **はずれ20枚（No.201〜220・2ページ）を10/15に追加**＝合計220枚・はずれ158。`.html` が生成元 |
| `抽選/当選者記録.pdf` | 当選者の受領記録（78行）。**金券の受渡しの証憑** |
| `抽選/当選者記録.html` | 生成元 |

- 印刷 → 裁断 → **点線で二つ折り**（表紙は天地逆に刷ってあるので折ると正立）。
  **厚めの紙**で（普通紙は等級が透ける）。中が見えない箱へ
- 1人10秒：QRを読む → くじを引く（戻さない）→ 当たりはその場で記録・受領サイン
- **くじ220枚（200＋追加はずれ20）で打ち切り**（参加賞は続行）。**追加分も最初から箱に混ぜる**。余ったギフトカードは返金可なので余る側に倒す
- 乱数は `seed=20261017` 固定＝刷り直しても同じ並び
- 記録用紙は終了後、総務（会計）へ

## セットアップ（今年のデプロイ手順）

1. 配備：`cd rentai2026 && git push && ./deploy.sh --go -y`
   （DBは公開領域の外 `~/rentai_stamp/` にあるので rsync では触れない）
2. 本番の manage.php で：大会名・開催日を確認 → 抽選条件を確認 →
   **登録キーを発行（出展社数＋予備）→ 登録用紙を印刷**
3. 名札：`次期システム/make_meibo.py` が `生成物/名札_白・桃・当日予備.pdf` を出す→印刷
   （当日予備は `生成物/当日予備コード.csv` を読ませて白紙に）
4. **事前参加者の一括登録**（受付タップを飛び込みだけにする）：
   参加者名簿の参加○の行の参加証コードを登録APIへ流す。
   ```sh
   cd 次期システム
   awk -F, 'NR>1 && $5=="○" && $11!="" {print $11}' 生成物/参加者名簿.csv | while read c; do
     curl -s "https://rentai-chugoku.org/stamp/admin.php?admin=<受付の鍵>&api=register&n=$c"; echo
   done
   ```
   応答は JSON（`already:true`＝登録済み）。何度流しても安全（冪等）。
   **APIは受付の鍵が必須**（admin.php の認証の内側。鍵なしは403・鍵は manage.php で再発行可）
5. 本番前リセット：`./reset_db.sh --backup` → `--go`、または manage.php の「記録を初期化」
6. 受付用QRは **manage.php の「受付用QRを表示」** から（受付の鍵はDB化・再発行可。
   旧 `qr/admin/` の画像は廃止＝`_旧/` へ）。**鍵入りなので机に放置しない**
   （学生が読むと自分で抽選済みにできてしまう。手元に持つか裏返す）

  -v "$PWD/web:/var/www/html:ro" php:7.4-apache

## はまった点（来年のために）

いずれも半日を溶かした。**GASを使うならこの3つを最初に確認すること。**

1. **クエリ名に `c` を使わない。** Google の予約で、`?c=...` を付けると doGet に到達する前に
   Drive の「現在、ファイルを開くことができません」で 400 になる。名札は `n`、企業は `b` にした。
2. **`appsscript.json` に `oauthScopes` を明示列挙しない。** 必要な権限が欠けるとウェブアプリが
   同じ Drive エラーで開けなくなる。自動判定に任せる。
3. **HtmlService のリンクには `target="_top"` が要る。** iframe の中で動くので、
   付けないと「接続が拒否されました」になる。

そして**そもそも GAS を使わなくてよかった**。サイトがさくらにあるなら PHP で書けば、
CORS も匿名アクセスもリダイレクトも無関係で、速度は数十倍になる（記録1回37ms・本番実測）。

**iOS のコードスキャナは localStorage を保てない。** 読み取るたびに使い捨ての領域で開くため、
「学生が各ブースのQRを読んで貯めていく」方式は成立しなかった。
**スマホで貯める仕掛けを作るなら、状態はサーバに置くこと。**

**DBの置き場所にも注意。** `~/www` はさくらの既定ドメイン（www3796.sakura.ne.jp）の
公開領域なのでデータを置いてはいけない。ホーム直下（`~/rentai_stamp/`・権限700）に置く。

**QRの大きさ**（2026-09-16 実測）：名札 20〜25mm角、ブース 50mm角以上。
